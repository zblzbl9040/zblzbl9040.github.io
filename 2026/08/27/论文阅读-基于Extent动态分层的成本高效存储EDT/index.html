论文阅读：基于Extent动态分层的成本高效存储（EDT）

论文：Cost Effective Storage using Extent Based Dynamic Tiering

Abstract

为了降低结合SSD、SAS/FC、SATA的多层存储系统的存储成本，论文提出了基于Extent（迁移粒度）的动态分层存储解决方案EDT。EDT主要由两部分构成：

  • EDT-CA（配置顾问）：用来确定在满足特定工作负载的前提下，应该采购何种类型及数量的存储设备组合；
  • EDT-DTM（动态层管理器）：负责在系统运行时动态对各个extent进行分层存储的放置。

Introduction

在之前的多级分层存储的相关研究中存在着一些问题/挑战：

  1. 缺少有效的配置工具来帮助确定设备组合和数量；
  2. 多层数据放置策略多为静态或粗粒度，不能根据工作负载动态调整，导致资源浪费；
  3. 现有方案没有充分利用动态合并数据和关机空闲设备以节省能耗的机会。

为了解决这些挑战，作者提出了一种基于Extent的动态分层存储解决方案（Extent-based Dynamic Tiering，EDT），主要组成部分是：

  • 配置顾问（EDT-CA）：根据客户工作负载，模拟动态数据迁移，设计出满足需求的最低成本设备组合；
  • 动态层管理器（EDT-DTM）：在线监测工作负载，动态调整extent在不同存储层之间的分布，保证性能同时最大程度降低功耗（如数据合并以关闭空闲设备）。

Design Choices

为什么选择以Extent作为粒度进行数据放置？

作者分析，如果以整个Volume为单位进行数据迁移，可能会出现”一个Volume中只有10%热数据却整个卷占用SSD”的资源浪费，粒度太粗；同时，细粒度的单位会带来额外的Extent级别的元数据开销和统计信息，需要平衡粒度和开销。

为什么选择动态分层？

作者这里选择以一个Epoch为一个周期重新评估并迁移Extent，而不是采用按天/月为单位作为一个时间尺度来进行迁移。这里主要考虑到工作负载的I/O强度随时间变化很大（非峰值时间远低于峰值）：

  1. 如果按峰值静态配置，非峰值时大量设备空转浪费资源；
  2. 如果按平均值配置，峰值时可能会性能崩溃。

为什么不仅仅以IOPS作为判断标准？

作者提到，现有的商业化产品大多只以IOPS决定数据放置在哪层，这种方式有一些缺陷：

  1. 忽略顺序/随机特性：一个Extent可能IOPS很高，但全是顺序访问，顺序访问在SAS/SATA上表现很好，根本不需要占用昂贵的SSD；
  2. 忽略带宽需求：顺序流占用的带宽资源与随机I/O不同；
  3. 忽略容量密度：高IOPS但容量很大的Extent，其I/O密度（IOPS/GB）可能很低，不值得放SSD。

Design

EDT整体结构如下：

作者预想EDT作为一个商用存储系统中的软件层，它依赖底层硬件和固件提供三个基础能力：

  • 多卷导出：能同时管理很多个逻辑卷；
  • 虚拟化映射：逻辑卷的地址空间被切成一个个Extent，这些Extent可以自由映射到不同设备类型的物理阵列上（SSD阵列、SAS阵列、SATA阵列）；
  • 非破坏性迁移：系统底层必须支持在后台”热迁移”数据块，且迁移过程中上层应用不能被中断或阻塞。

EDT-CA的工作逻辑

  • 按周期统计输入粒度：按Epoch采样时间序列数据，统计每个Extent在每个Epoch中的IOPS和带宽需求；
  • 按周期统计最低成本：EDT-CA会独立模拟每个Epoch。在某个Epoch中，如果某个Extent随机IOPS增加，就把它模拟放到SSD层；如果在下个Epoch它变成了顺序大流量，就把它模拟放到SAS层。模拟结束后，CA计算在这个Epoch内最大负载下需要的硬件设备种类和数量；
  • 取值：跑完某个时间内所有的Epoch后，CA按照得到的最大的设备种类和数量得到配置。

EDT-DTM的工作逻辑

  • 持续获取需求：每个Epoch结束，重新计算所有Extent的随机IOPS和带宽需求；
  • 资源消耗预测：评估如果把某个Extent放在SSD、SAS或SATA上，分别会消耗该层多少百分比的处理能力；
  • 动态迁移：根据评估结果，驱动后台迁移线程把数据块在层间搬动，并在空闲时执行整合逻辑（整合的是数据块）。

Data Collector

用来为EDT-DTM采集数据，包括传输大小、响应时间、逻辑块地址（LBA）、I/O发送的目标卷ID以及执行该I/O的存储阵列。在数据块级别统计随机I/O次数与传输字节量，结合指数加权移动平均（EWMA）计算瞬时带宽与随机IOPS以支撑动态分层决策；在阵列级别聚合总IOPS与平均响应时间以触发过载限流检测。

Resource Consumption Model

然后，将该Extent放置在能够满足其性能要求且成本最低的那个层级上。遍历完所有的Extent后，就将所有的Extent分成了多个类（这里的类指的就是不同类型的存储设备）。

这里举个例子，对于某个Extent：

  • 放在SSD上：SSD单价100元，RC = 0.1（因为SSD极快，只需消耗它10%的能力）→ 成本 = 100 × 0.1 = 10元
  • 放在SAS上：SAS单价20元，RC = 0.4（SAS慢一些，需消耗40%能力）→ 成本 = 20 × 0.4 = 8元
  • 放在SATA上：SATA单价5元，但RC = 1.2（SATA太慢了，100%能力都不够用，超过1.0）→ 成本 = 5 × 1.2 = 6元（但此方案无效）

对于每个类，分别汇总其性能资源消耗（RCp = ΣRC(Ep,D)）和容量资源消耗（RCc = ΣRC(Ec,D)），取这两个值中的最大值即为该类所需的总资源量；将该总和向上取整到最接近的整数，即可计算出该层级所需的设备数量。

独立地对每一个Epoch重复上述过程，以识别出每个周期内能够实现最低成本的各层级设备数量，最后合并每个周期。

Dynamic Tier Manager

EDT-DTM由三个模块组成：分层聚合模块TAC、限流检测与校正模块、迁移器模块。

TAC算法会在每个Epoch结束后生成一个新的Extent放置方案。TAC算法需要两个输入：(1) 从正在运行的系统中获取的每个Extent当前的随机I/O速率和带宽；(2) 存储系统中每个阵列的容量（以字节计）、随机I/O速率能力和带宽能力。

同样，对于每个Extent E和设备类型D，该Extent分配到该设备上的功耗负担占比：extent_power(E,D) = power(D) × RC(E,D)。遍历所有Extent后，上述计算就将所有Extent分成了多个类，这就是分层的过程。

之后，分配到每个层级的Extents随后会按照它们的RC值进行排序，并使用首次适应递减启发式算法放置到各个阵列中。当已分配到该层级的Extents超出了该层级的可用性能（即已分配Extents的资源消耗指标总和超过1），或者该层级在可用阵列中空间不足时，剩余未分配的Extents会被降级到对该Extent来说具有次低功耗负担的层级。这个打包过程会对所有层级重复进行，从而将Extents整合到每个层级中数量最少的阵列中。如果某个Extent已经处于正确的层级，并且它所在的阵列在本周期内将保持通电状态，那么它将保留在上一个周期的位置，从而节省迁移开销。

限流器每分钟监控一次所有活跃阵列。如果某阵列平均响应时间飙升（表明请求排队过长），即判定为限流，此时立即暂停所有由TAC发起的、非紧急的待处理迁移。从过载阵列中，找出最少数量的Extent进行迁移，这些Extent的总资源消耗（ΣRC）必须至少占该阵列当前总负载的**50%**；如果迁走50%后依然限流，就继续重复迁移，直到响应时间恢复正常。在迁移时优先将该Extent迁移至更高层级的设备上。

迁移器负责实际搬动数据，由下面几个机制组成：

机制名称 具体做法 目的
1. 串行化准入控制 每块物理盘同一时刻只能参与一个迁移任务。源盘或目标盘繁忙时，请求直接排队等待。 防止多任务并发导致磁头乱跑，保护业务I/O。
2. 切片+限速 把大Extent拆成小传输单元；动态调整发送速度 平滑迁移流量，避免瞬时占满带宽。
3. 即搬即用 搬完一个小单元，该单元的I/O路由立刻切换到目标盘，不用等整个Extent搬完。 让热数据秒级获得高性能，快速缓解拥堵。
4. 超时清空 若Epoch结束，旧迁移计划还没搬完，直接清空旧队列，插入新周期的计算任务。 绝不纠结过时的任务，始终响应最新负载。
5. 保留旧位置 如果Extent本就在正确层级且所在盘不会关机，直接跳过，不迁移。 避免无意义的搬动，节省资源与SSD寿命。

总结

EDT是分层存储领域里工程味道很浓的一篇工作，它的价值在于把”买多少设备”和”数据放哪里”两个问题统一到同一个资源消耗模型（RC）下求解：

模块 解决的问题 关键手段
EDT-CA 采购规划：买什么、买多少 按Epoch模拟迁移，取最大负载配置
Resource Model 统一容量与性能的度量 RC = max(性能占比, 容量占比)
TAC + 首次适应递减 每周期的最优放置与节能整合 按功耗成本分层，尽量集中以关闭空闲设备
限流器 运行时性能保护 迁走过载阵列≥50%负载的Extent
迁移器 迁移不伤业务 串行准入、切片限速、即搬即用

几个设计取舍在今天看来依然有参考价值：Extent粒度在元数据开销与迁移灵活性之间取平衡；用Epoch周期而非天/月粒度响应负载波动；判断标准综合随机IOPS、带宽和容量密度而非单一IOPS。这些思路对后续动态分级存储（包括冷热数据分层、AI时代的数据价值分级）的研究都有直接的借鉴意义。
